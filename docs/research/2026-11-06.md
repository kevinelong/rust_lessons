## What this implies for `rust_lessons`

1. **The course has no practice artefacts at all.** Every section is read-and-run; nothing
   asks the learner to produce or repair code. Parsons and faded-example evidence says
   practice is where the learning happens, and the deck this course mirrors had
   `problems/` pairs that the Rust version never inherited. **Highest-value gap.**
2. **Subgoal labels are missing from both prose and examples.** The lessons explain *what*
   (`Vectors: the growable list`) but rarely name the subgoal structure a solver would use
   ("decide the type → build the shape → choose the traversal"). Margulieux's result is
   precisely that labelling these in expository text improves transfer.
3. **The ownership visualisation is evidence-aligned and under-used.** Section 17's diagrams
   match what RustLIVE found helps; there is only one such figure, and Track B is where
   novices fail most.
4. **Compiler-message literacy is not taught.** The CMU study puts compiler errors among the
   top barriers; the course shows one `E0004` in a diagram and never teaches reading an
   error. This is the Rust equivalent of the Ruby cohort's
   `ruby-lecture-reading-error-messages` lesson, which the Python deck also lacked.
5. **Nothing here measures learning.** The 88 tests measure *code*, not comprehension. Any
   claim about teaching quality is currently unfounded; the course can only claim
   correctness and reproducibility.

## Decisions taken from this pass

* Practice problems are generated from the lesson's own code (Parsons first, faded after),
  not written by hand — the same "one source" discipline as the slides and video.
* Subgoal labels go into the lesson prose where a procedure is taught (sections 07, 08, 11,
  16 first), because that is where the evidence is strongest.
* Compiler-message literacy becomes its own section (Track B, 21), not a sidebar.
* No claim of "better learning" will be made until there is an artefact a learner's score
  can be measured on. Parsons output is the first such artefact.

## Still unknown / next searches

* Does narration-driven video help at all versus reading the same text? The literature on
  video versus text is contested and mostly measures engagement, not retention.
* Are Kokoro's vowels intelligible to non-native listeners? Needs actual listeners.
* Whether `evcxr` notebook execution survives a chapter-sized lesson; ours are 2–3 cells.
* Prior art for **faded Parsons in Rust specifically** — nothing found yet.
* Spacing/interleaving schedule for a ten-session course: what does the evidence say about

## Later the same day

Faded variants and retrieval checks are generated too: **60 practice files**, three per
section, none authored by hand. Two lessons from writing them, both kept as comments in
`src/bin/quiz.rs` because each looked right until printed:

* Splitting prose on `.` broke inside `**bold**`, parentheses and `i.e.`, producing prompts
  like "Moving**: assigning or passing a value…".
* Treating a line as a sentence broke because the lessons are hard-wrapped at ~95 columns,
  so a "sentence" was half of one. Joining the beat into a paragraph first, then splitting
  only where a full stop precedes a capital, fixed it.
