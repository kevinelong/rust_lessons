## What is now fragile

- The quiz's worked-example skip ends at the next `#` heading. An example with no heading after it
  would swallow every later item in that section, silently. A `cargo run --bin quiz` diff is the
  check that catches it; the quiz floor of four items may not.
- `subgoals_travel_with_a_worked_example` pins `checked == 4`. Adding a fifth procedural section
  fails the test until the number and the acceptance text are revisited - deliberate, but it will
  read as a surprise to whoever adds that section.
- The `Output:` lines are checked by the test for presence only; nobody asserts they still match
  the code. The examples are quoted as `text`, so the compiler does not read them either. A change
  to `Table`, `word_counts` or the standard library's `max_by_key` tie rule would leave a stale
  output line in the prose.
- §07's worked example prints `Some(6) None` for a `-`-free input; if a later edit makes `spread`
  return `0` for an empty list, the prose promise ("never a 0 that reads as a real gap") and the
  code diverge and only a reader notices.
